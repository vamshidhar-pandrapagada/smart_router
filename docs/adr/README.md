# Architecture decision records

Decisions that shape the design, the process (CI workflows included) or the runtime dependencies of smart-router are recorded here, each in the same pull request as the change it explains.

## When to write one

| Change | ADR? |
|---|---|
| A design choice: architecture, file format, interface, default | Yes |
| A change to CI workflows, or to how work is reviewed or released | Yes |
| A new runtime dependency | Yes |
| An internal refactor, a test layout change, a bug fix | No |

## Format

- **File name:** `ADR-YYYYMMDD-xxxx-short-title.md`, where `xxxx` is 4 random hex characters, so two branches never pick the same name. `swerepo adr new "Title"` creates one from [TEMPLATE.md](TEMPLATE.md).
- **Frontmatter:** `id`, `title`, `status` (`PROPOSED | ACCEPTED | SUPERSEDED | REJECTED`), `date`, `scopes`, `invariants`, `supersedes`, `superseded_by`.
- **Sections:** Context, Decision (with alternatives considered), Enforced Invariants, Consequences.
- To replace a decision, write a new ADR with `supersedes:` set, and set `status: SUPERSEDED` and `superseded_by:` on the old one. Never delete an ADR.
